# DIATLAS preprocessing

This folder holds the preprocessed copy of the DIATLAS diatom dataset used to
train our diffusion model and classifiers for diatom DVCEs. Everything here is
generated by [`diatoms/prepare_diatlas.py`](prepare_diatlas.py)
and can be rebuilt at any time (about 1 minute on 16 CPU workers).

```bash
# from the DVCEs repo root
~/miniconda3/envs/python_38_dvces_cu111/bin/python diatoms/prepare_diatlas.py
# options: --root /mnt/diatoms/datasets/diatlas --out data/diatlas --seed 0
#          --val_frac 0.1 --test_frac 0.1 --workers 16
```

Images that already exist are skipped. To rebuild after changing the split or
the image processing, delete `256/` first.

## Source data

- **Dataset:** DIATLAS, the French freshwater diatom atlas image dataset
  ([Zenodo 16260887](https://zenodo.org/records/16260887)), located at
  `/mnt/diatoms/datasets/diatlas`.
- **Content:** 38,719 light-microscopy images (brightfield/DIC) cut out of 14
  regional atlas PDFs, labelled with 866 taxa in 119 genera. Metadata is in
  `diatoms.csv`: path, taxon (`official_taxon`), genus (`genus_code`), source
  atlas, page, scale and a `connective` flag.
- **What the raw images look like:** tight crops of a single diatom, mostly
  grayscale with occasional color tints, elongated (median 72×216 px, typical
  aspect ratio about 3:1), long axis vertical, with background brightness that
  varies between atlases. Some crops carry a 1-pixel light frame from the atlas.

## Step 1: Filtering

We drop the **1,940 connective (girdle) views** (`connective == True`). They
show the diatom from the side and look very different from the valve views
that make up the rest of the data.

**36,779 images remain**, covering 864 taxa in 119 genera. No other images are
removed; class-size filtering for the classifier happens later, when the label
granularity is chosen.

## Step 2: Train/val/test split

The split is made once, over all images, and does not depend on whether the
classifier later predicts species or genus. The diffusion model trains on
train+val only, so it never sees the test images we later explain.

**Grouping by atlas page.** Images from the same atlas page share imaging
conditions and often come from the same sample. To avoid leakage, every
`(source, page)` group (1,920 groups) goes entirely into one split.

**Why not random page assignment.** The atlases are sorted by species, so
almost every page (1,863 of 1,920) holds a single taxon, and one page usually
holds 15–30% of that taxon's images. Assigning pages at random sent whole
species into one split: in our first attempt, 63 of the 108 larger species had
no test images. A proportional (greedy) assignment still failed, because one
page is too large to fit a 10% test share.

**What we do instead (per-species page split, seed 0):**

1. Each page is assigned to its majority taxon.
2. For each taxon, its pages are sorted from smallest to largest, with random
   order among equal sizes.
3. If the taxon has **3 or more pages**, the smallest pages go to **test** until
   about 10% of its images are reached, the next ones to **val** until about
   10%, and the rest to **train**. Each split gets at least one page, train
   always keeps at least one, and test or val stops adding pages before going
   over 20%.
4. If the taxon has **2 pages**, the larger goes to train and the smaller
   alternates between test and val from one taxon to the next.
5. If the taxon has **1 page**, it goes to train.

**Result:**

| Split | Images | Share | Pages | Taxa present |
|---|---|---|---|---|
| train | 25,969 | 71% | 1,124 | 862 |
| val | 6,222 | 17% | 376 | 370 |
| test | 4,588 | 12% | 420 | 369 |

Val and test end up larger than 10% because pages are coarse units: a species'
smallest page is often more than 10% of its images.

Coverage for the two candidate classifier label sets
(details in `split_report.txt`):

| Label set | Classes | Test images per class |
|---|---|---|
| Species (taxa) with ≥100 images | 108 | median 20, max 97; only BNEG (0) and NMIC (1) have fewer than 5 |
| Genera with ≥200 images | 41 | min 13, median 57, max 603 |

## Step 3: Per-image processing

Every image is turned into a 256×256 single-channel PNG:

1. **Grayscale.** Converted with PIL `convert('L')`. This removes atlas color
   tints, which carry no biological information and could become a shortcut.
2. **Trim the frame.** 2 pixels are cut from each edge, removing leftover atlas
   frame lines. This is skipped for images with a side of 16 px or less.
3. **Orientation.** If the crop is wider than tall, it is rotated 90° so the
   long axis is vertical, as in the rest of the data.
4. **Resize.** Scaled so the **long side is 256 px**, keeping the aspect ratio
   (Lanczos). The median raw height is 216 px, so this is close to native
   resolution along the long axis. Narrow images are upscaled.
5. **Pad to square.** Centered on a 256×256 canvas filled with the **median of
   the image's outer 2-pixel border**, so the padding matches the image's own
   background instead of adding a white frame.

256×256 matches the OpenAI unconditional diffusion checkpoint
(`256x256_diffusion_uncond.pt`), so we can fine-tune it and reuse the DVCE code
without architecture changes. Images are saved with one channel to save space;
data loaders replicate it to 3 channels (RGB), which the diffusion model and
the classifiers expect.

## Output layout

```
data/diatlas/
├── README.md            this file
├── splits.csv           one row per image (see below)
├── split_report.txt     split sizes and per-class test coverage
├── montage.png          64 random processed images, for a visual check
└── 256/
    └── <split>/<taxon>/<atlas>/<name>.png     e.g. 256/test/AAMB/IDF/AAMB_018.png
```

Total size: 587 MB.

`splits.csv` columns:

| Column | Meaning |
|---|---|
| `path` | processed image, relative to `data/diatlas/` |
| `orig_path` | original image, relative to the DIATLAS root |
| `taxon` | `official_taxon` code (species / infraspecific taxon) |
| `genus` | `genus_code` |
| `source` | atlas PDF ID (see DIATLAS `sources.csv`) |
| `page` | page in that atlas PDF |
| `split` | `train`, `val` or `test` |
| `orig_w`, `orig_h` | size of the original image in pixels |

## Known limitations

- **Visible crop edges.** Where an image's background isn't uniform, the
  constant padding shows a faint brightness step at the original crop
  boundary. We expect the diffusion model to learn this as background.
- **Upscaling.** Narrow or small crops are enlarged, so some images look soft.
- **Scale is not normalized.** Each image is resized to fill the canvas, so
  absolute size (µm) is lost. The `scale` column in `diatoms.csv` is kept for
  reference but isn't used.
- **Atlas style still differs.** Background brightness and contrast vary by
  atlas. A classifier could use this as a shortcut; we plan to check for it
  (see `DIATOM_PLAN.md`, section 4).
- **Split proportions** are 71/17/12, not the 80/10/10 the script options name,
  for the page-granularity reason given above.
