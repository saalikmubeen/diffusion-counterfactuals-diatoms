# DIATLAS, native-size preprocessing (crop 224, canvas 256)

Second preprocessed copy of DIATLAS. It replaces the first one
(`data/diatlas`, stretch-to-fit) for training the diffusion model and the
classifier we explain with DVCE. Generated by
[`diatoms/prepare_diatlas_nativesize.py`](prepare_diatlas_nativesize.py)
in about 35 seconds:

```bash
~/miniconda3/envs/python_38_dvces_cu111/bin/python diatoms/prepare_diatlas_nativesize.py
```

## The name

| Part | Meaning |
|---|---|
| `nativesize` | diatoms keep their **native pixel size**: no stretching, no rescaling |
| `crop224` | diatoms longer than **224 px** are center-cropped to 224 (as in the PadCropDiatom preprocessing) |
| `canvas256` | each image is a **256×256** canvas (the diffusion model's input size) |

## Why a second preprocessing

The first version (`data/diatlas`) stretched every diatom to fill a 256×256
image. That erases **size**, a trait that separates many species. A classifier
can't learn species well from it:

| Classifier (independent ResNet-18, 759 species, our val split) | Accuracy |
|---|---|
| on `data/diatlas` (stretch-to-fit), before / after 15 epochs of fine-tuning | 30% / 37% |
| on his own preprocessing, before any fine-tuning | **85%** |

(Details: `diatoms/COMMANDS.md`, section 8.)

## What was done per image

This is the `PadCropDiatom` transform
([`diatoms/padcrop_transform.py`](padcrop_transform.py)), with a
larger canvas:

1. **No rescaling.** His code can rescale to a common µm/pixel, but with the
   DIATLAS `scale` values that made his model worse (69% vs 75%), so images
   keep their native pixel size.
2. **Long axis vertical**, by transposing (as in his code).
3. **Center-crop to 224 px** if longer. This affects 17,038 images (46%): long
   diatoms lose their ends.
4. **Seamless padding.** A 256×256 canvas is filled with the image's median
   gray, and the diatom (**flipped upside down**, as in his code) is
   Poisson-blended into the center (OpenCV `seamlessClone`, `NORMAL_CLONE`,
   since our OpenCV 4.5.5 has no `NORMAL_CLONE_WIDE`).
5. **Grayscale**, saved as a single-channel PNG.

## How the classifier must see these images

The **center 224×224** of every image is pixel-identical to the independent classifier's
224×224 input. In DVCE the classifier must get that **center crop, not a
resize**. On 1,000 val images:

| Classifier input | Accuracy |
|---|---|
| center crop 224 of these images (= his input) | **84.2%** |
| these images resized 256 → 224 | 70.0% |
| these images at full 256×256 | 11.0% |

The diffusion model sees the full 256×256 image.

## Split and contents

- **Same images and split as `data/diatlas`**: 36,779 images, connective
  views dropped, page-grouped split train / val / test = 25,969 / 6,222 / 4,588.
- Same folder layout: `256/<split>/<taxon>/<atlas>/<name>.png`.
- `splits.csv` columns: `path, orig_path, taxon, genus, species_code, source,
  page, split, orig_w, orig_h, cropped` (`cropped` = 1 if longer than 224 px).
  `species_code` is the classifier's label. 3,158 images have an empty
  `species_code` (identified only to genus); the classifier training skips them.
- `montage.png`: 64 random images.
- Size: 440 MB.

## Known limitations

- **Long diatoms are cropped** (46%): their ends, sometimes diagnostic, are
  missing. That is inherited from the PadCropDiatom preprocessing, which his
  classifier depends on.
- **Not truly physical size.** Atlases differ slightly in µm per pixel (most
  ~0.08, Bourgogne ~0.06–0.11), and we don't correct for it, because
  correcting hurt the classifier.
- Upside-down flip: harmless for DVCE (diatoms are roughly symmetric), kept
  only to match his classifier's training.

## Second split: random image split (`splits_random.csv`)

Besides the page-grouped split (`split` column in `splits.csv`, also the
`256/<split>/` folder names), there is a **random image split**, 80/10/10,
used for the classifier runs with `--split_mode random`
(`diatoms/COMMANDS.md`, section 14). Each image's split comes from a hash of
its original path (`random_split_of` in `diatoms/train_classifier.py`), so it
is fixed and reproducible. `splits_random.csv` lists it for every image
(`split_random`), next to the page split (`split_page`).

The images are the same files; only the split labels differ. **The folder
names show the page split, not the random one.** In the random split, photos
of one atlas page are spread over train, val and test, so test accuracy
measures recognition of seen pages, not of new samples.
